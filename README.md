# فروشگاه معیلی — فروشگاه آنلاین مواد غذایی

یک فروشگاه فارسی و کاملاً RTL برای فروش محصولات غذایی و کالاهای روزمره، با رابط موبایل‌محور (نوار پایین شبیه اپ‌های فروشگاهی)، حساب کاربری واقعی مشتری، دسته‌بندی رنگی محصولات، پنل مدیریت، Supabase Auth، Database و Storage.

## امکانات

- صفحه اصلی مینیمال و موبایل‌محور با نوار پایین (خانه / دسته‌بندی / سبد خرید / حساب کاربری)
- حساب کاربری مشتری با شماره موبایل؛ ایمیل به کاربر نمایش داده نمی‌شود و شماره موبایل شناسه ورود است.
- هر مشتری فقط سفارش‌های خودش را می‌بیند — بدون جستجوی عمومی با شماره موبایل
- دسته‌بندی رنگی محصولات، قابل مدیریت کامل از پنل ادمین (افزودن، ویرایش رنگ/نام، حذف)
- هر محصول می‌تواند به چند دسته‌بندی همزمان تعلق داشته باشد
- جستجوی سریع محصولات و فیلتر تخفیف‌دار/پرفروش/جدید
- محاسبه خودکار درصد تخفیف از قیمت مصرف‌کننده و قیمت فروشگاه
- سبد خرید با کنترل موجودی
- ثبت سفارش دائمی در Supabase، متصل به حساب مشتری
- شماره سفارش یکتا مثل `ORD-58321472`
- فاکتور مناسب موبایل و چاپ، همراه با اطلاعات پرداخت کارت‌به‌کارت
- پنل مدیریت: افزودن محصول با عکس مستقیم از گالری، مدیریت سفارش‌ها و دسته‌بندی‌ها
- ذخیره عکس در Supabase Storage، نه Base64 در دیتابیس
- RLS برای کنترل دسترسی؛ هیچ کاربری به سفارش کاربر دیگر دسترسی ندارد
- محاسبه قیمت سفارش در تابع امن دیتابیس و نه از مقدار قیمت ارسالی frontend

## اطلاعات فروشگاه (در کد ثابت شده)

نام، آدرس، تماس، کانال ایتا و اطلاعات کارت پرداخت در `app.js` (شیء `STORE`) و در `invoice.html` قرار دارند. برای تغییر این اطلاعات همان‌جا را ویرایش کنید.

## 1. ساخت پروژه Supabase

1. وارد Supabase شوید و یک پروژه جدید بسازید (یا از پروژه قبلی استفاده کنید — فایل SQL ایمن و idempotent است).
2. از بخش SQL Editor فایل `supabase.sql` را کامل اجرا کنید.
3. اجرای موفق SQL جدول‌های `products`, `admins`, `orders`, `order_items`, `categories`, `product_categories`، توابع RPC و bucket عکس را ایجاد/به‌روزرسانی می‌کند.

## 2. فعال‌سازی ثبت‌نام مشتری‌ها

در Supabase به برای حساب مشتری، رابط سایت فقط شماره موبایل می‌گیرد. پیاده‌سازی فعلی برای جلوگیری از نیاز به سرویس SMS، شماره را در Auth به یک شناسه داخلی تبدیل می‌کند؛ مشتری هیچ ایمیلی وارد نمی‌کند. در Supabase گزینه Confirm email را خاموش کنید تا ثبت‌نام بلافاصله قابل ورود باشد.
اگر «Confirm email» فعال باشد، مشتری باید قبل از سفارش ایمیلش را تأیید کند؛ برای راحتی مشتری‌ها می‌توانید آن را از تنظیمات Authentication خاموش کنید.

## 3. ساخت حساب مدیر

1. در Supabase به Authentication → Users بروید.
2. Add user را انتخاب کنید و ایمیل و رمز عبور مدیر را بسازید.
3. UUID همان کاربر را کپی کنید.
4. در SQL Editor این دستور را با UUID واقعی اجرا کنید:

```sql
insert into public.admins(user_id) values ('UUID-USER-HERE');
```

توجه: حساب مدیر یک ردیف عادی در `auth.users` است، فقط داخل جدول `admins` هم ثبت شده. کلید service_role را به هیچ وجه داخل پروژه frontend قرار ندهید.

## 4. تنظیم Supabase در پروژه

در فایل‌های `app.js`, `admin.js` و `invoice.html` این دو مقدار باید یکسان باشند:

```js
const CONFIG = {
  SUPABASE_URL: "https://YOUR-PROJECT.supabase.co",
  SUPABASE_ANON_KEY: "YOUR_PUBLIC_ANON_KEY"
};
```

فقط Publishable/Anon key را در frontend قرار دهید. service_role فقط سمت سرور/محیط امن است.

## 5. دسته‌بندی محصولات

از پنل مدیریت → تب «دسته‌بندی‌ها»: نام و رنگ دلخواه را وارد و اضافه کنید (مثلاً لبنیات، گوشت، برنج و حبوبات). سپس هنگام افزودن یا ویرایش هر محصول، از بخش «دسته‌بندی‌های محصول» یک یا چند دسته را تیک بزنید. مشتری‌ها این دسته‌ها را به‌صورت تراشه‌های رنگی در صفحه اصلی و شیت پایین «دسته‌بندی» می‌بینند.

## 6. Storage

فایل SQL به‌صورت خودکار bucket عمومی `product-images` را می‌سازد و Policyها را ایجاد می‌کند. عکس محصول مستقیم از گالری گوشی آپلود و URL عمومی آن در `products.image_url` ذخیره می‌شود.

## 7. اجرای پروژه

```bash
python -m http.server 8080
```

سپس `http://localhost:8080` را باز کنید. باز کردن مستقیم فایل با `file://` برای پروژه‌های دارای Supabase توصیه نمی‌شود.

## 8. انتشار روی GitHub Pages / Vercel / Netlify

پروژه کاملاً static است؛ کافی است فایل‌ها را در ریپو قرار دهید و Pages/Vercel/Netlify را به آن وصل کنید — بدون نیاز به Build Command.

## 9. امنیت و RLS

- کاربران عمومی فقط محصولات و دسته‌بندی‌ها را می‌خوانند.
- مدیریت محصولات، دسته‌بندی‌ها و سفارش‌ها فقط برای UUIDهایی که در `admins` ثبت شده‌اند مجاز است.
- هر مشتری فقط سفارش‌های خودش (`user_id = auth.uid()`) را می‌بیند؛ سیستم قدیمی جستجوی سفارش با شماره موبایل به‌طور کامل حذف شده.
- ثبت سفارش از طریق RPC امن `create_order` و فقط برای کاربر واردشده انجام می‌شود.
- فاکتور هر سفارش (`get_order_by_number`) فقط به صاحب سفارش یا مدیر نمایش داده می‌شود.
- قیمت‌ها و موجودی از دیتابیس خوانده می‌شوند و frontend نمی‌تواند قیمت نهایی سفارش را تحمیل کند.
- هنگام ثبت سفارش، snapshot قیمت و نام محصول در `order_items` ذخیره می‌شود؛ بنابراین تغییر قیمت محصول در آینده فاکتور قدیمی را تغییر نمی‌دهد.
- کلید service_role در هیچ فایل frontend قرار نگرفته است.

## 10. افزودن درگاه پرداخت آنلاین در آینده

فعلاً پرداخت به‌صورت کارت‌به‌کارت و ارسال رسید انجام می‌شود. برای اتصال درگاه آنلاین:
- ایجاد یک Edge Function یا backend امن برای ساخت Payment Session
- ارسال مبلغ نهایی از سفارش ذخیره‌شده، نه مبلغ ارسالی مرورگر
- ثبت `payment_status` و `transaction_id` در جدول سفارش
- تأیید callback در سمت سرور

## نکته مهم درباره نسخه نمایشی

اگر URL و Anon Key هنوز تنظیم نشده باشند (یعنی هنوز `YOUR_` در CONFIG است)، صفحه اصلی چند محصول نمونه نمایش می‌دهد اما بخش‌های حساب کاربری و ثبت سفارش واقعی کار نمی‌کنند. برای استفاده واقعی باید Supabase را طبق مراحل بالا متصل کنید.

- پروفایل قابل ویرایش و سفارش‌های اختصاصی هر مشتری
- پنل کامل مشتریان و خروجی چاپ/PDF
- دسته‌بندی پایین صفحه و دسته‌بندی چندتایی برای هر محصول
- نمایش/مخفی‌سازی محصول با 👁
- کنترل مستقل «قیمت فروشگاه فعال است»
- کنترل مستقل نمایش نشان درصد تخفیف
- بنر و لوگو قابل تغییر از مدیریت
- تنظیم هزینه ارسال و فعال/غیرفعال کردن ارسال
- انتخاب تحویل حضوری یا ارسال در مرحله نهایی سفارش
- اطلاعات کارت و متن پرداخت در فاکتور
- نوار پایین: خانه / جستجو / سفارش‌ها / حساب کاربری

### نکته مهم
بعد از جایگزینی فایل‌ها، فایل `supabase.sql` را **کامل** در SQL Editor همان پروژه اجرا کنید تا ستون‌ها، پروفایل‌ها، تنظیمات، امنیت و تابع جدید ثبت سفارش ایجاد شوند.

## احراز هویت مشتریان
مشتری فقط شماره موبایل و رمز عبور وارد می‌کند. سایت شماره موبایل را به یک ایمیل داخلی و مخفی تبدیل می‌کند و از Email Auth خود Supabase استفاده می‌کند؛ مشتری هیچ ایمیل واقعی وارد نمی‌کند.

در Supabase فقط این تنظیمات لازم است:
- Authentication → Sign In / Providers → Email: روشن
- Confirm email: خاموش
- Phone provider: خاموش و نیازی به Twilio نیست

اگر Confirm email روشن باشد، Supabase بعد از ثبت‌نام جلسه ورود را تحویل نمی‌دهد و مشتری وارد سایت نمی‌شود.

## پرفروش‌ها
در پنل مدیریت هنگام افزودن/ویرایش محصول، گزینه «محصول در پرفروش‌ها نمایش داده شود» را فعال کنید تا محصول در بخش پرفروش‌های صفحه اصلی نمایش داده شود.
