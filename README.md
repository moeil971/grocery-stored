# فروشگاه روزمره — فروشگاه آنلاین مواد غذایی

یک فروشگاه فارسی و کاملاً RTL برای فروش محصولات غذایی و کالاهای روزمره، با رابط موبایل‌محور، پنل مدیریت، Supabase Auth، Database و Storage.

## امکانات

- صفحه اصلی مدرن و RTL
- جستجوی سریع محصولات
- محصولات ویژه، تخفیف‌دار، پرفروش و جدید
- محاسبه خودکار درصد تخفیف از قیمت مصرف‌کننده و قیمت فروشگاه
- سبد خرید با کنترل موجودی
- ثبت سفارش دائمی در Supabase
- شماره سفارش یکتا مثل `ORD-58321472`
- فاکتور مناسب موبایل و چاپ
- پیگیری سفارش با شماره موبایل
- پنل مدیریت
- افزودن محصول و انتخاب عکس مستقیم از گالری گوشی
- ذخیره عکس در Supabase Storage، نه Base64 در دیتابیس
- RLS برای کنترل دسترسی
- محاسبه قیمت سفارش در تابع امن دیتابیس و نه از مقدار قیمت ارسالی frontend

## 1. ساخت پروژه Supabase

1. وارد Supabase شوید و یک پروژه جدید بسازید.
2. از بخش SQL Editor فایل `supabase.sql` را کامل اجرا کنید.
3. اجرای موفق SQL باید جدول‌های `products`, `admins`, `orders`, `order_items` و bucket عکس را ایجاد کند.

## 2. ساخت حساب مدیر

1. در Supabase به Authentication → Users بروید.
2. Add user را انتخاب کنید و ایمیل و رمز عبور مدیر را بسازید.
3. UUID همان کاربر را کپی کنید.
4. در SQL Editor این دستور را با UUID واقعی اجرا کنید:

```sql
insert into public.admins(user_id) values ('UUID-USER-HERE');
```

کلید service_role را به هیچ وجه داخل پروژه frontend قرار ندهید.

## 3. تنظیم Supabase در پروژه

در فایل‌های `app.js`, `admin.js` و `invoice.html` این دو مقدار را جایگزین کنید:

```js
const CONFIG = {
  SUPABASE_URL: "https://YOUR-PROJECT.supabase.co",
  SUPABASE_ANON_KEY: "YOUR_PUBLIC_ANON_KEY"
};
```

فقط Publishable/Anon key را در frontend قرار دهید. service_role فقط سمت سرور/محیط امن است و در این پروژه اصلاً داخل HTML/JS استفاده نشده.

## 4. Storage

فایل SQL به‌صورت خودکار bucket عمومی `product-images` را می‌سازد و Policyها را ایجاد می‌کند.

عکس محصول از موبایل با:

```html
<input type="file" accept="image/*">
```

انتخاب و مستقیماً در Storage آپلود می‌شود. URL عمومی آن در `products.image_url` ذخیره می‌شود.

## 5. اجرای پروژه

برای تست سریع می‌توانید فایل‌ها را با یک static server اجرا کنید:

```bash
python -m http.server 8080
```

سپس:

```text
http://localhost:8080
```

را باز کنید.

باز کردن مستقیم فایل با `file://` برای پروژه‌های دارای Supabase توصیه نمی‌شود.

## 6. انتشار روی Vercel

1. پروژه را در GitHub قرار دهید.
2. وارد Vercel شوید.
3. Import Project را بزنید.
4. Repository را انتخاب کنید.
5. چون پروژه static است، Build Command لازم نیست.
6. خروجی را روی دامنه Vercel منتشر کنید.

Netlify نیز با Drag & Drop یا اتصال Git قابل استفاده است.

## 7. امنیت و RLS

- کاربران عمومی فقط محصولات را می‌خوانند.
- مدیریت محصولات فقط برای UUIDهایی که در `admins` ثبت شده‌اند مجاز است.
- مدیریت سفارش‌ها فقط برای مدیران مجاز است.
- ثبت سفارش از طریق RPC امن `create_order` انجام می‌شود.
- قیمت‌ها و موجودی از دیتابیس خوانده می‌شوند و frontend نمی‌تواند قیمت نهایی سفارش را تحمیل کند.
- هنگام ثبت سفارش، snapshot قیمت و نام محصول در `order_items` ذخیره می‌شود؛ بنابراین تغییر قیمت محصول در آینده فاکتور قدیمی را تغییر نمی‌دهد.
- کلید service_role در هیچ فایل frontend قرار نگرفته است.

## 8. افزودن درگاه پرداخت در آینده

پیشنهاد معماری:
- ایجاد یک Edge Function یا backend امن برای ساخت Payment Session
- ارسال مبلغ نهایی از سفارش ذخیره‌شده، نه مبلغ ارسالی مرورگر
- ثبت `payment_status` و `transaction_id` در جدول سفارش
- تأیید callback در سمت سرور

## نکته مهم درباره نسخه نمایشی

اگر URL و Anon Key هنوز تنظیم نشده باشند، صفحه اصلی با چند محصول نمونه نمایش داده می‌شود و سفارش آزمایشی در localStorage شبیه‌سازی می‌شود. برای استفاده واقعی باید Supabase را طبق مراحل بالا متصل کنید.
